# 多站自动保活小仓库

> 用 GitHub Actions 定时访问你名下的多个网站，防止免费主机账号被当作"闲置账号"回收。
> 不需要服务器，不需要密码，配置一次之后完全不用管。

## 它做什么

不少免费主机商会清理长期没人访问的账号。本仓库用一个定时任务，每天自动以普通访客的身份访问你的网站若干次，让账号保持活跃状态。

它只做一件事——打开你的网页。因此：

- **不需要保存账号密码**，即使仓库是公开的，也不存在信息泄漏问题
- **不占用你的设备**，任务在 GitHub 的服务器上运行
- **不需要任何第三方工具或付费服务**
- **不依赖任何第三方 Action**，只用 GitHub 官方组件和系统命令

## 工作原理

- **触发时间**：北京时间每天 00:00、04:00、08:00、12:00、16:00、20:00
- **频率**：每天 6 次，间隔 4 小时
- **访问方式**：HTTP 请求，自动跟随跳转，携带正常浏览器标识
- **故障隔离**：某个网站打不开，不会影响其他网站继续访问
- **自动续期**：距上次提交超过 45 天时，自动提交一次空记录

### 为什么要"自动续期"

GitHub 有一条规则：**公开仓库如果 60 天没有任何活动，里面的定时任务会被自动停用**。

本仓库内置了一个续期任务：只要发现距离上次提交已经超过 45 天，就自动提交一个空记录，把活跃度计时器重新归零。因为 45 天小于 60 天，所以它总会在被停用之前先执行一次，从而实现**永久运行、无需人工干预**。

平时它是静默的，不会产生多余记录。

## 适用与不适用

| 情况 | 是否适用 | 说明 |
| --- | --- | --- |
| 靠"有人访问"判断活跃的免费主机（alchosting、TinkerHost、AeonFree、Byet.host 等） | ✅ 适用 | 访问一次页面即可产生活跃记录 |
| 靠"登录面板 / SSH"保活的主机（Serv00、x10hosting、GoogieHost 等） | ❌ 不适用 | 必须真正登录，单纯访问网页无效 |
| 频繁休眠的平台（Render、Fly.io 等，十几分钟无请求就休眠） | ❌ 不适用 | 这类需要几分钟一次的频率，本仓库做不到 |
| 静态托管（GitHub Pages、Cloudflare Pages、Netlify） | ⚪ 不需要 | 这类不会因为没人访问而删除 |
| 自己的付费主机 / VPS | ⚪ 不需要 | 本来就没有闲置回收机制 |

## 快速开始

1. **建仓库**：新建一个**公共仓库**（Public），名字随意，例如 `web-keepalive`。
2. **开权限**：进入 `Settings` → `Actions` → `General`，找到 **Workflow permissions**，选择 **Read and write permissions**，点 `Save` 保存。

   > 这一步不做的话，自动续期任务会因为没有提交权限而失败。

3. **放配置**：新建文件 `.github/workflows/keepalive.yml`，内容见下方"日常维护"，填入你自己的网址。
4. **提交**：点 `Commit changes` 保存。
5. **测试**：进入 `Actions` 标签 → 左侧选 **多站4小时轮询保活** → 点 `Run workflow` 手动触发一次，等待约 30 秒。

看到绿色对勾即表示配置成功。

## 日常维护

### 怎么加一个网站

打开 `.github/workflows/keepalive.yml`，找到 `matrix.include` 这一段，在末尾追加两行：

```yaml
          - name: "网站备注名"
            url: "https://你的网址/"
```

### 怎么删一个网站

把对应的 `name` 和 `url` 两行一起删掉即可。

### 改的时候注意

- **缩进必须对齐**：`- name:` 前面有 10 个空格，`url:` 前面有 12 个空格，多一点少一点都会报错
- **网址必须带 `https://` 开头**，不能只写域名
- 备注名只是给你自己看的，随便起

## 常见问题

**会收费吗？**
不会。公共仓库使用 GitHub 提供的标准运行环境，完全免费。

**需要一直开着自己的电脑吗？**
不需要。任务在 GitHub 的服务器上执行，和你的设备无关，关机断网都不影响。

**每天访问 6 次，会不会被主机商当成攻击？**
不会。每天 6 次、每次只打开首页，就是一个普通访客的正常访问量。反而不建议把频率调得太高，那种才容易触发限流。

**为什么续期任务显示"未达45天阈值，本次跳过"？**
这是正常的。说明距上次提交还没到 45 天，不需要续期，任务按设计跳过。

**网站加了 Cloudflare 之后访问失败了怎么办？**
见下方"故障排查"中的 403 一项。

**能不能把 Serv00 也放进来？**
不能。Serv00 靠"登录"判断活跃，单纯访问网页无效，需要单独用登录类方案处理。

## 故障排查

进入 `Actions` → 点开某次运行记录 → 展开对应的步骤，看输出的 HTTP 状态码。

| 状态码 / 现象 | 含义 | 处理办法 |
| --- | --- | --- |
| `200` | 访问成功 | 无需处理 |
| `301` / `302` | 页面跳转 | 正常现象，请求已跟随跳转，仍算有效访问 |
| `403` | 被防火墙拦截 | 网站若套了 Cloudflare，关闭 Bot Fight Mode，或在 Cloudflare 的 WAF → Tools → IP Access Rules 中把 GitHub 的访问 IP 设为 Allow |
| `404` | 地址写错 | 检查网址路径是否正确 |
| `000` / 连接超时 | 网站暂时打不开 | 在浏览器里手动访问一次确认；偶发失败下次会自动恢复 |
| 报错含 `Repository access blocked` | 引用了已被停用的第三方 Action | 本项目不依赖第三方 Action，如自行添加过请移除 |
| 警告含 `Node.js 20 is deprecated` | 引用的 Action 版本过旧（提示级，非错误） | 把 `actions/checkout@v4` 改成 `@v5` 即可消除 |
| 报错含 `Permission denied`（续期任务） | 仓库没有写权限 | 参见"快速开始"第 2 步，把 Workflow permissions 改为 Read and write |
| 到点没有触发 | GitHub 定时任务延迟 | 高负载时可能延迟十几分钟，属正常现象，不影响保活效果 |

## 注意事项

- **仅用于保活你自己的网站**，不要拿去做任何批量探测或压测
- **不要盲目提高频率**，每天 6 次已经远超绝大多数免费主机的活跃判定要求
- **靠"登录"保活的主机不适用**，请单独采用登录类方案
- 各家免费主机对"活跃"的具体判定标准并不公开，本仓库采用"每个网站都定期访问"的保守策略，以覆盖最严格的情况
